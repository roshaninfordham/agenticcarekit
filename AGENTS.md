# AGENTS.md — invariants for agents working in this repo

You are editing `agenticcarekit` itself, not a project generated by it. These are not
preferences. A change that violates one of them is wrong even when the tests pass.

`CLAUDE.md` is a symlink to this file. Generated projects get their own, shorter
`AGENTS.md` written by `ack init` — do not confuse the two.

---

## 1. Never move a `Sensitive` value without the policy engine

`Sensitive.unwrap_for(provider, policy)` — which delegates to `Policy.unwrap` — is the
only sanctioned path that reveals a wrapped value on its way to a provider. Do not add
a second one.

- Never call a network provider on data inside a `Sensitive` scope outside
  `Policy.unwrap`.
- Never read `_Sensitive__value`, `#value`, or any internal slot. The name-mangled field
  is reachable; reaching it is a review finding.
- `dangerously_reveal()` is the one greppable raw accessor. If you add a call to it, the
  diff must explain why the data stays on-device by construction.
- Do not put a value, or a redacted span, into a `TraceEvent` payload. Payloads carry
  decisions, category names, and counts.
- Do not widen `[policy] egress` to make a test pass. E303 firing is the feature.

New bypass idea? Write the test that closes it in `tests/test_policy_bypass.py` before
you write anything else.

## 2. The contracts are frozen

`agenticcarekit.kernel.contracts` is the only import surface every other tier is built
against. If a contract does not fit, amend it — **code + JSON Schema +
`docs/CONTRACTS.md` in one commit** — never patch around it downstream.

| Contract | Code | Schema |
|---|---|---|
| 1 `Capabilities` / `Provider` | `kernel/contracts/provider.py` | `spec/schemas/capabilities.schema.json`, `provider-spec.schema.json` |
| 2 `Sensitive` / `PolicyContext` | `kernel/contracts/policy.py` | — |
| 3 `@tool` | `kernel/contracts/tools.py` | `spec/schemas/tool-manifest.schema.json` |
| 4 `TraceEvent` | `kernel/contracts/trace.py` | `spec/schemas/trace-event.schema.json` |
| 5 `ack.toml` | `kernel/contracts/config.py` | `spec/schemas/ack-toml.schema.json` |

Renaming any of these breaks the conformance adapters in **both** languages:
`build_ollama_chat`, `ensure_supported`, `Capabilities.missing`, `Policy.unwrap`,
`Policy.check_provider`, `TraceEvent.from_dict` / `to_dict`, `bytes_egressed`,
`AckConfig.load` / `to_toml`.

## 3. Every tool ships a mock

`@tool(permissions={...}, mock=...)` fails at **import time** with **E502** when the
mock is missing, and **E503** for a permission outside `network | sensitive | writes`.
Do not work around the decorator. The mock is what makes `ack demo --offline` real, so
it must return canned data realistic enough to demo.

## 4. Error codes live in `spec/errors.json` first

Add the registry entry, *then* raise it in code. A code raised but not registered is a
test failure — `tests/test_conformance_registry.py` enforces it. Ranges: `E0xx`
environment · `E1xx` model/provider/network · `E2xx` capability · `E3xx` policy · `E4xx`
config · `E5xx` generation · `E6xx` eval. Every entry needs `title`, `what`, `why`, and
a literal `fix` command.

## 5. Prompts are `.md` files, never string literals

Anything a model reads lives under a `prompts/` directory and is loaded from disk:
`capabilities/*/prompts/`, `evals/prompts/`, `blueprints/*/templates/app/prompts/`.
`ack eject prompts` copies them into user source; a prompt inlined in Python breaks that
promise.

## 6. `--json` on every command, always

Non-TTY is first class. Every `ack` command supports `--json` and emits the stable
envelope `{envelope_version, ok, command, version, elapsed_ms, data, error}` with
`envelope_version = 1`. The sidecar returns the same envelope over HTTP and MCP.
Failure sets a non-zero process exit status so a verification loop can read it. Never
print progress that is not real, never add artificial delay, never build a full-screen
TUI, keep terminal output append-only, respect `NO_COLOR` and `FORCE_COLOR`, degrade
below 80 columns.

## 7. No telemetry, ever

No analytics, no phone-home update check, no crash reporting, no "anonymous usage
statistics". Provider API keys are checked for **presence only** — never read the value,
never log it, never put it in an error payload or a serialized `MachineFacts`.

## 8. Determinism

Identical inputs produce a byte-identical tree. No timestamps, no absolute paths, no
`uuid4()` or `datetime.now()` in generation or synthetic data; sorted file iteration,
sorted JSON keys. `SyntheticGenerator(seed)` draws from exactly one `random.Random`.

## 9. Ejectability is a promise

Drop the blueprint, keep the packs. Drop the packs, keep the capabilities. Drop the
capabilities, call the kernel directly. Concrete providers expose their raw client as
`.client`. Do not add an abstraction that cannot be walked around.

## 10. The sidecar binds loopback

`ack serve` defaults to `127.0.0.1` and writes a `0600` token file at
`<project>/.ack/serve.token`. A non-loopback bind requires the explicit `--allow-remote`
flag. Do not change that default, do not weaken the token check, and do not add an
endpoint that reaches a provider without going through `Policy` — the whole point of the
sidecar is that enforcement lives in one process that thin clients never touch. The MCP
tool surface is a closed list (`serve/mcp_server.py::TOOL_NAMES`); adding one is a
product decision, not a refactor.

## 11. Where code goes

| Change | Directory |
|---|---|
| Provider quirk, transport, fallback | `packages/agenticcarekit/kernel/providers/` |
| Egress enforcement, redaction plumbing | `packages/agenticcarekit/kernel/policy/` |
| Trace emitter, sinks, analysis | `packages/agenticcarekit/kernel/trace/` |
| Voice / agents / extract / rag | `packages/agenticcarekit/capabilities/<name>/` |
| Domain models, redactor implementations, synthetic data | `packages/agenticcarekit/packs/<pack>/` |
| Generated project templates | `packages/agenticcarekit/blueprints/<name>/templates/` |
| CLI commands, detection, recommendation | `packages/agenticcarekit/cli/` |
| Sidecar, HTTP routes, MCP tools | `packages/agenticcarekit/serve/` |
| Schemas, error registry, conformance corpus | `spec/` |
| Docs, `llms.txt`, changelog, registry | `docs/`, repo root |

Tests are flat and named per workstream: `tests/test_<area>_<topic>.py` — for example
`tests/test_policy_bypass.py`, `tests/test_providers_builder.py`,
`tests/test_cli_init.py`, `tests/test_serve_http.py`. Keep new tests in that shape; do
not create subdirectories under `tests/`.

Do not edit `pyproject.toml` to add a dependency. Report the need instead — the runtime
deps are `typer`, `rich`, `questionary`, `pydantic`, `httpx`, `psutil`, plus the `serve`
extra (`fastapi`, `uvicorn`, `sse-starlette`, `mcp`), and that list is deliberately
short.

## 12. Public functions carry a runnable docstring example

Doctests are executed. `ack check` runs the contract doctests as its selftest, and
retrieval surfaces the examples. A public function with no example is incomplete.

## Verification — run these, do not assume

```bash
# full suite, from the repo root
uv run pytest -q

# conformance, both adapters — both must report 69/69
uv run python spec/conformance/runner.py -- uv run python spec/conformance/adapters/python.py
python3 spec/conformance/runner.py node spec/conformance/adapters/typescript.mjs

# lint and format
uv run ruff check packages tests spec
uv run ruff format --check packages tests spec

# doctests for one area
uv run pytest --doctest-modules packages/agenticcarekit/kernel/policy/ -q

# the fast agent loop, inside a generated project
ack check --json      # lint + selftest, 30 s budget, non-zero exit on failure
```

The TypeScript adapter needs a build first, and its pytest gate **skips** without one —
a skip is not a pass:

```bash
cd packages/ts && npm install && npm run build && npm test
```

### Two things that will otherwise waste your time

- Known-failing today, do not chase it:
  `tests/test_cli_commands.py::test_eval_with_a_golden_set_but_no_provider_chain_names_the_gap`
  (asserts the behaviour from before `kernel.providers.factory.provider_for` landed).
- `uv run pytest` from the repo root **writes generated fixture files into the repo
  root** — `README.md`, `AGENTS.md`, `CLAUDE.md`, `ack.toml`, `Makefile`, `app/`,
  `prompts/`, `providers/`, `.cursor/`, `.github/copilot-instructions.md`. Run
  `git status` afterwards and clean up. Never run a writing `ack` command (`init`,
  `new`, `eject`, `sync`) with the repo root as the working directory; pass an explicit
  path into a scratch directory instead.

## 13. Git

Do not run state-changing git commands — no `commit`, `checkout`, `restore`, `reset`,
`add`, `stash`, `push`. Read-only `git log`, `git diff`, `git status` are fine. The
human or the orchestrator commits.
