# Error registry

Every error agenticcarekit can raise, generated from [`spec/errors.json`](../spec/errors.json) — the single registry the CLI, both language implementations, and the MCP surface all read.

**Registry version `1.0.0` · 34 codes.**

Do not edit this file by hand. Regenerate it when `spec/errors.json` changes.

---

## The rule

A new code is **added to `spec/errors.json` first**, then raised in code. A code raised in the implementation but missing from the registry is a test failure — `tests/test_conformance_registry.py` enforces it, which is how `ack explain <code>` can promise never to come back empty.

Every entry carries four fields: **what** happened, **why** it is refused rather than worked around, and a literal **fix** command you can paste. `ack explain E203` prints the long form; `ack explain E203 --json` returns it structured under the standard envelope, and the same content is served over MCP.

```
$ ack explain E203

  E203  Model does not support a required input modality

    what   a request or blueprint needs an input modality (e.g. audio) this model lacks.
    why    native audio input is available on gemma4:e2b and gemma4:e4b only.

  Fix:
    ack init --model gemma4:e4b-mlx
```

## Detail

### E0xx — bootstrap / environment

#### `E001` · Python version too old

- **What** — agenticcarekit requires Python 3.11 or newer.
- **Why** — the kernel uses typing and tomllib features introduced in 3.11.
- **Fix** — `uv python install 3.12 && uv run ack doctor`

#### `E010` · Ollama is not installed

- **What** — no ollama binary was found on PATH.
- **Why** — the local model path runs through the Ollama daemon.
- **Fix** — `brew install ollama   # or: curl -fsSL https://ollama.com/install.sh \| sh`

#### `E011` · Ollama daemon is not running

- **What** — the ollama binary exists but the daemon did not answer on 127.0.0.1:11434.
- **Why** — model pulls and generation need the daemon up.
- **Fix** — `ollama serve   # then re-run your command`

#### `E012` · Microphone dependency not installed

- **What** — the local mic adapter needs the optional sounddevice package and it is not installed.
- **Why** — audio capture is optional — the voice loop runs fully offline against MockASR without it.
- **Fix** — `uv pip install sounddevice   # or use MockASR / the Twilio adapter`

#### `E013` · Optional extra not installed

- **What** — a command needs an optional dependency group that is not installed (e.g. the [serve] extra).
- **Why** — heavy optional dependencies stay out of the core install; the feature names its extra instead.
- **Fix** — `uv pip install "agenticcarekit[serve]"   # the error's fix line names the exact extra`

#### `E020` · Not enough disk space for the selected model

- **What** — free disk at the model directory is below model size × 1.15.
- **Why** — a partial pull wastes bandwidth and leaves a corrupt blob.
- **Fix** — `free up space, or pick a smaller model: ack init --model gemma4:e2b`

#### `E021` · Not enough RAM for the selected model

- **What** — available RAM is below the model's working-set requirement (size / 0.6 rule).
- **Why** — a model that swaps is slower than a smaller model that fits.
- **Fix** — `pick a smaller model: ack init --model gemma4:e2b   # or use a hosted primary`

#### `E022` · Model variant does not fit this platform

- **What** — the selected variant targets different hardware (e.g. an -mlx tag off Apple Silicon).
- **Why** — -mlx builds run only on Apple Silicon; CUDA-sized picks assume an NVIDIA GPU.
- **Fix** — `let detection choose: ack init   # or pick the base tag, e.g. gemma4:e4b`

#### `E030` · Project root not writable

- **What** — agenticcarekit needed to create a file under the project root and the filesystem refused.
- **Why** — read-only mounts, permissions, or a missing directory.
- **Fix** — `ack serve --path <a directory you can write to>`

### E1xx — model / provider / network

#### `E101` · Model pull failed

- **What** — the model download did not complete.
- **Why** — network interruption or registry error; pulls are resumable.
- **Fix** — `re-run the same command — the pull resumes where it stopped`

#### `E102` · Provider request failed

- **What** — the provider returned an error or timed out.
- **Why** — transient provider/network failure; the fallback chain covers this when configured.
- **Fix** — `check 'ack doctor', or configure a fallback: [model] fallback = "cerebras:gemma-4-31b"`

#### `E110` · Network unreachable

- **What** — a network probe or provider call could not reach its host.
- **Why** — offline machine, captive portal, or firewall.
- **Fix** — `ack demo --offline   # everything runs against mocks with networking disabled`

#### `E120` · Provider API key missing

- **What** — a hosted provider is configured but its API key env var is not set.
- **Why** — hosted providers authenticate via environment variables; agenticcarekit never stores key values.
- **Fix** — `export CEREBRAS_API_KEY=...   # presence is checked, the value is never logged`

#### `E130` · Sidecar token rejected

- **What** — a request to ack serve arrived without a valid bearer token.
- **Why** — every endpoint except /v1/health requires the local token so other local processes cannot drive the sidecar silently.
- **Fix** — `Authorization: Bearer $(cat .ack/serve.token)`

### E2xx — capability mismatch

#### `E201` · Context window too small

- **What** — the blueprint's required context exceeds the model's context window.
- **Why** — long transcripts or documents will silently truncate otherwise — agenticcarekit refuses instead.
- **Fix** — `pick a 256K-context model: ack init --model gemma4:12b`

#### `E202` · Tool calling not supported

- **What** — the blueprint requires native function calling and this model/provider pair does not declare it.
- **Why** — prompt-hacked JSON is not a substitute; agenticcarekit only uses native function calling.
- **Fix** — `ack init --model gemma4:e4b   # all Gemma 4 tags declare tool calling via Ollama`

#### `E203` · Model does not support a required input modality

- **What** — a request or blueprint needs an input modality (e.g. audio) this model lacks.
- **Why** — native audio input is available on gemma4:e2b and gemma4:e4b only.
- **Fix** — `ack init --model gemma4:e4b-mlx`

#### `E204` · Model does not support a required output modality

- **What** — the request needs an output modality the model cannot produce.
- **Why** — Gemma 4 output is text only on every variant — speech output requires a separate TTS provider.
- **Fix** — `ack add voice   # wires a TTS provider next to the model`

### E3xx — policy and privacy violations

#### `E301` · Sensitive value blocked at egress boundary

- **What** — a Sensitive[T] value was about to reach a public-cloud provider with no redactor declared.
- **Why** — sensitivity is a type, not a convention — un-redacted PHI never crosses the boundary.
- **Fix** — `declare a redactor: [policy] redactor = "healthcare.phi"   # or keep egress = "device"`

#### `E302` · Declared redactor not found

- **What** — ack.toml names a redactor that no installed pack provides.
- **Why** — the policy engine refuses to guess — a silently missing redactor would be an open boundary.
- **Fix** — `ack doctor --json \| grep redactors   # then fix [policy] redactor in ack.toml`

#### `E303` · Egress attempted above configured limit

- **What** — a provider with a broader egress class than [policy] egress was invoked.
- **Why** — the project declared a stricter boundary than this provider satisfies.
- **Fix** — `use a device/trusted provider, or deliberately raise [policy] egress in ack.toml`

### E4xx — project config

#### `E401` · Invalid ack.toml

- **What** — ack.toml exists but could not be parsed or a field is malformed.
- **Why** — usually a hand-edit; the file is meant to be edited, so errors name the exact key.
- **Fix** — `ack sync   # reconciles and rewrites a valid ack.toml, preserving your values`

#### `E402` · ack.toml missing a required section

- **What** — [project] and [model] are required and one is absent.
- **Why** — the runtime cannot pick a model or blueprint without them.
- **Fix** — `ack sync`

#### `E403` · Invalid egress class in ack.toml

- **What** — [policy] egress is not one of device, trusted-network, public-cloud.
- **Why** — the privacy boundary is defined over exactly these three classes.
- **Fix** — `set [policy] egress = "device"`

#### `E404` · No ack.toml in this directory

- **What** — the command needs a project and none was found here.
- **Why** — you are outside a generated project, or init has not run.
- **Fix** — `ack init`

#### `E410` · Unknown blueprint

- **What** — the named blueprint is not installed.
- **Why** — first-party blueprints are voice-care, care-copilot, on-device.
- **Fix** — `ack init --blueprint on-device`

#### `E411` · Unknown pack

- **What** — the named pack is not installed.
- **Why** — packs are discovered via entry points; an uninstalled pack is invisible.
- **Fix** — `uv pip install <pack-package>   # or: ack new pack`

### E5xx — generation / templates

#### `E501` · Template rendering failed

- **What** — a blueprint template did not render.
- **Why** — template and context drifted — this is a bug in the blueprint, not your project.
- **Fix** — `re-run with --json for the failing template path, and file an issue`

#### `E502` · Tool declared without a mock

- **What** — @tool was applied with no mock implementation.
- **Why** — every tool ships a mock — it is what makes `ack demo --offline` real.
- **Fix** — `@tool(mock=mock_yourtool, ...)  # return canned, realistic data`

#### `E503` · Unknown tool permission

- **What** — a permission outside network/sensitive/writes was declared.
- **Why** — permissions are a closed set so generated projects can reason about them.
- **Fix** — `use permissions={"network"} (or "sensitive", "writes")`

#### `E504` · Structured extraction failed validation

- **What** — the model's output did not match the requested schema, and the single repair attempt did not fix it.
- **Why** — extraction returns validated data or it fails — a half-parsed clinical record is worse than none.
- **Fix** — `ack demo --json   # 'details' carries both raw outputs; tighten the schema or the prompt`

### E6xx — eval

#### `E601` · Eval golden set missing

- **What** — ack eval found no golden set for this blueprint/pack.
- **Why** — evals score against committed golden files; none exist yet.
- **Fix** — `ack eval --init   # scaffolds a golden set from the pack's clinical eval sets`

#### `E602` · Eval scoring failed

- **What** — the judge model call failed while scoring.
- **Why** — judge runs use the same provider chain and can hit the same network errors.
- **Fix** — `re-run; or score offline against exact-match only: ack eval --offline`

#### `E603` · Generated demo failed

- **What** — the project's demo exited non-zero.
- **Why** — usually a missing model, a broken edit in app/, or a capability mismatch surfaced at run time.
- **Fix** — `ack demo --offline   # runs against mocks; then ack doctor for environment causes`

---

## Known drift

- **E601's fix references `ack eval --init`, which is not implemented.** Create a JSONL golden set at `evals/golden.jsonl` in your project instead (`{"id": ..., "input": ..., "expected": ...}` per line), then run `ack eval --offline`.
- **E012** is raised by the optional mic adapter when `sounddevice` is missing. `sounddevice` is deliberately not a declared dependency; `MockASR` and the Twilio adapter need no audio hardware at all.
